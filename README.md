# ops-causal-rag

小さな自動化基盤（定時ジョブ・Slackボット・記録パイプライン）の**障害の因果連鎖を辿って答えるQAシステム**です。依存グラフの探索と文書検索を組み合わせ、「Aが落ちると何に波及するか」「Bが動かない原因の候補はどこか」に、**引用つき・検証済み**で答えます。

```
質問 → [グラフ] 因果経路を展開（波及方向/原因方向を自動判定）
     → [検索] 経路上のノードに触れるrunbook＋文字2-gram一致で上位k件
     → [LLM] 経路と文書だけを根拠に回答（[rbXX]引用を強制）
     → [検証] 引用が提供文書内に実在するか確認。不正なら差し戻し
```

## 設計判断

1. **埋め込みを使わない説明可能な検索**: 文書10本・ノード18個の規模では、「なぜこの文書が選ばれたか」を因果経路とキーワード一致で完全に説明できる方が、運用の切り分けに役立つ。全ての検索結果に選定理由（`why`）が付く
2. **引用の機械検証**: LLMの回答は `[rbXX]` 引用を必須とし、**提供していない文書の引用（=幻覚）を検証で弾いて差し戻す**。回答の正しさをLLMの誠実さに任せない
3. **グラフ票は2票で頭打ち**: 経路上のノードに多く触れる文書がキーワード的に正しい文書を押し出す失敗が実際に起きたため、「経路に触れているか」だけを票にした
4. **評価は検索と回答を分離**: 検索は決定的に測り（LLM不要）、回答は引用妥当率で測る

## 評価結果（12問・k=4）

| 検索モード | 文書再現率 | 因果ノード再現率 |
|---|---|---|
| グラフ＋キーワード | 0.941 | 0.964 |
| キーワードのみ | 1.000 | —（経路を提示できない） |

回答評価（LLM=claude-sonnet-5・引用検証つき）: 引用妥当率 （実測値）

**正直な考察**: この規模・この評価セットでは、文書再現率だけならキーワード検索で足りた（質問の語彙が文書の語彙と揃っているため）。グラフの価値は文書選択ではなく、(1)**因果経路そのものを回答の骨格として提示できる**こと (2)検索理由を説明できること、にあった。唯一の取りこぼしは「子プロセス」と「サブプロセス」の**表記ゆれ**で、文字一致ベースの本質的限界。同義語辞書で延命できるが、語彙が開いていく規模では埋め込み検索への切り替えが必要になる——その判断材料が得られたのがこの実験の収穫。

## 使い方

```bash
python3.13 -m venv .venv && .venv/bin/pip install pytest
.venv/bin/python -m pytest                        # テスト17本（LLM不要・決定的）
PYTHONPATH=src .venv/bin/python -m ocrag.cli "ネットワークが落ちると何に影響が出る？"  # 要: Claude Code CLI
```

## コーパスについて

runbook 10本は、筆者が実際に運用している自動化基盤（launchd定時ジョブ・Slack常駐ボット・GAS記録・Vercelホスティング）の実運用知見をもとに、本リポジトリ用に書き下ろしたものです。依存グラフも同基盤の実構成を単純化したものです。

## 限界

- コーパス10本・ノード18個の最小構成。評価12問は筆者作成（第三者検証なし）
- 表記ゆれに弱い（上記）。回答の「内容の正しさ」は引用妥当率でしか測っておらず、意味的な正誤の自動評価は未実装
- グラフは静的定義。実システムからの自動抽出は対象外

## AI利用について

実装はClaude Code（AIコーディングツール）を全面的に使っています。グラフ・コーパス・評価セットの内容と設計判断は人間の運用経験に基づき、検索の正しさはテスト17本とCIで担保しています。
